# Internals

Parts of the library you normally do not touch, documented for completeness.

## `arena::Arena`

A small boundary-tag allocator over caller memory: 8-byte-aligned blocks, first fit, coalescing on free. It uses `u32`
offsets instead of pointers (0 = null) and never touches the heap. `World` uses it for chunk sections.

| Method | Description |
|--------|-------------|
| `Arena::empty()` / `Default` | an arena with no memory |
| `unsafe init(mem: *mut u8, size)` | take ownership of `mem` (8-byte aligned, valid for `size` bytes, exclusively owned while in use) |
| `alloc(bytes) -> u32` | offset of a block, 0 if full |
| `release(off)` | free a block |
| `ptr(off) -> *mut u8` | the block's memory |
| `capacity()`, `used()`, `largest_free()` | statistics; `largest_free` is a fragmentation indicator |

## `inflate::zlib_inflate`

```rust
pub fn zlib_inflate(input: &[u8], out: &mut [u8], verify: bool) -> Option<usize>
```

An allocation-free zlib decoder (RFC 1950/1951), table-driven (10-bit lookup, 64-bit bit buffer), ~7 KB of stack.
Returns the number of bytes written, or `None` on corrupt data or if `out` is too small. `verify` checks the Adler-32
checksum. Used by `Client` for compressed frames. There is no deflate: the client always sends uncompressed frames,
which servers accept.

## `ids`

Generated by `tools/gen_ids.py`. For every state and direction there is an enum of **version-agnostic** packet ids
and a table that maps them to the ids on the wire:

| Enum | Table | Packets |
|------|-------|---------|
| `HandshakingSb` | `HANDSHAKING_SB_TABLES` | 2 |
| `StatusCb`, `StatusSb` | `STATUS_CB_TABLES`, `STATUS_SB_TABLES` | 2, 2 |
| `LoginCb`, `LoginSb` | `LOGIN_CB_TABLES`, `LOGIN_SB_TABLES` | 4, 2 |
| `PlayCb`, `PlaySb` | `PLAY_CB_TABLES`, `PLAY_SB_TABLES` | 80, 34 |

Each enum has `COUNT`, `ALL` (all values in order), `NAMES` (the minecraft-data names, e.g. `"MapChunk"`) and
`from_u8`. Each table is `[Tables; 4]`, indexed by `Version::table_index()`:

```rust
pub struct Tables { pub w2a: &'static [u8], pub a2w: &'static [u8] }   // 0xFF = not present in this version

use mcscon::ids::{PlayCb, PLAY_CB_TABLES};
let t = &PLAY_CB_TABLES[version.table_index()];
let wire = t.a2w[PlayCb::Chat as usize];          // wire id of Chat in this version
let name = PlayCb::NAMES[t.w2a[0x0F] as usize];   // (check for 0xFF first) agnostic name of wire id 0x0F
```

## Feature flags

| Feature | Default | Adds |
|---------|---------|------|
| `std` | yes | `posix::TcpTransport`, `std` conveniences. Without it the crate is `#![no_std]` |
| `capi` | no | the C API (`src/capi.rs`, `include/mcscon.h`); implies `std`; `libmcscon.a` is produced with `cargo rustc … --crate-type staticlib` |

The crate depends only on `libm` (for deterministic maths). No panics are used for error handling of input data.

## `capi`: the C ABI

`src/capi.rs` (feature `capi`) is the implementation of [`include/mcscon.h`](../../include/mcscon.h):

- `McBot` is a heap-allocated struct holding a `Session<'static, TcpTransport>`, the chat callback, a start
  `Instant`, and the `Vec`s the session borrows. The session is declared first so it is dropped before the memory it
  points into; the `Vec`s never reallocate, so their heap memory stays put when they move into the `Box`.
- `mc_bot_poll` = `Session::poll` with a sink that forwards chat to the C callback (copied into a NUL-terminated stack
  buffer), followed by `Session::update(start.elapsed())`.
- Every other function is a one-line forward to a `Session` field or method.

[Extending the C API](../c-api.md#extending-the-c-api) shows how to add functions. Internally, `lib.rs` also contains
`escape()`, a zero-cost compiler barrier placed before user callbacks run, because C/C++ callbacks may legitimately
read or send through the bot while Rust holds references to it.
